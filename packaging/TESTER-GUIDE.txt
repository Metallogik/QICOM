QICOM - testing instructions
============================

The bundle includes Python and the application's libraries: there is no
need to install Python. Unpack it and launch it, keeping the whole folder.
A compatible operating system and architecture are still required; on
Linux, system graphics libraries not included in the bundle may be needed.

The automatic check of the bundles is a smoke test on the build system.
It is not equivalent to a test on every version of the operating system or
on physical monitors with different DPI. The details and the limits are
documented in packaging/DISTRIBUTION.md in the repository, section
Compatibility boundary.

The downloads on qicom.ch are "full" builds (quantitative and qualitative
analysis plus radiomics) without the learned metrics: see the last section.
Builds made from a release tag also include the learned metrics, and a
"base" build (without radiomics) can be made on request. Practical
requirements: minimum 8 GB RAM/4 cores; recommended 16 GB/6-8 cores; 32 GB
for large 3D volumes, many ROIs or learned metrics.

The downloaded artifact contains the archive and a file with the .sha256
suffix. The checksum identifies exactly the build you received and lets IT
compare it with the authorised one. It does not replace a digital
signature.

To verify the archive before extracting it:

  Windows PowerShell (replace the name if necessary):

    $expected = (Get-Content .\QICOM-windows-x64.zip.sha256).Split()[0]
    $computed = (Get-FileHash .\QICOM-windows-x64.zip -Algorithm SHA256).Hash
    $computed.ToLower() -eq $expected.ToLower()

  macOS:

    shasum -a 256 -c QICOM-macos-arm64.zip.sha256

  Linux:

    sha256sum -c QICOM-linux-x64.tar.gz.sha256
    sha256sum -c QICOM-linux-x64.deb.sha256     (Debian/Ubuntu package)

The result must be True on Windows or OK on macOS/Linux. After extraction,
SHA256SUMS also contains the hash of each individual file in the bundle,
including the three attribution files described below.

Next to the application you will find:

  THIRD_PARTY_LICENSES.txt    licences of the third-party components
                              included in THIS build, generated from the
                              environment it was built from
  THIRD_PARTY_INVENTORY.json  the same list in machine-readable form:
                              version, origin and licence of every
                              component
  qicom-sbom.cdx.json         the same set as a CycloneDX SBOM, for whoever
                              in your organisation has to inventory the
                              software

They are meant for IT: they describe exactly what the build you received
contains, and they are covered by the same SHA256SUMS as the rest of the
bundle.

IMPORTANT: keep the folder whole. The executable does not work if it is
moved out of its folder, because the libraries it loads sit next to it.


macOS 14 (Apple Silicon / arm64)
--------------------------------
This build does NOT work on Intel Macs.
The intended build system is macOS 14; later versions require checking the
build you received. Launching on macOS 11-13 is not guaranteed.

1. Unpack the zip (double-click).
2. Drag QICOM.app wherever you like (for example into Applications).
3. On first launch macOS blocks the app with a message such as
   "cannot be opened because it is from an unidentified developer" or
   "the app is damaged".

   The build is not signed or notarised by Apple. If the checksum matches
   and your organisation's policy allows the test, try to open it, then go
   to System Settings > Privacy & Security, scroll to the bottom and press
   "Open Anyway".

   If instead an antivirus/EDR reports malware or quarantines the app, do
   not bypass it: write down the product, the detection name and the hash,
   then contact IT.


Windows 10 from 1809 / Windows 11 (x64)
---------------------------------------
These are the expected desktop targets. The automatic smoke test runs on
GitHub's Windows Server runner, not on Windows 10 and 11 separately.
Windows 7/8/8.1, 32-bit systems and a native Windows ARM bundle are not
supported.

Recommended: QICOM-windows-x64.zip, which contains the installer

1. Right-click the zip > "Extract All...", then double-click
   QICOM-Setup.exe.
2. The classic setup wizard opens: welcome page with the description of
   QICOM, licence, information about QICOM, destination folder, progress
   bar with the percentage, and finish.
   By default QICOM goes into Program Files (C:\Program Files\QICOM) for
   all users, and Windows asks for administrator permissions. Without those
   permissions choose "Install for me only" in the first window: QICOM then
   goes into your own programs folder.
3. At the end you can launch QICOM right away; afterwards you will find it
   in the Start menu (and on the desktop, if you left the box ticked).
4. To uninstall: double-click "Uninstall QICOM" in the installation folder
   (next to qicom.exe), or Settings > Apps > Installed apps > QICOM >
   Uninstall. Your projects and preferences are not deleted (they are in
   %LOCALAPPDATA%\qicom, see below).

Alternatively, QICOM-windows-x64-portable.zip (portable version, no
installation):

1. Right-click the zip > "Extract All..." into a real folder (for example
   on the Desktop).
   DO NOT launch the executable directly from inside the zip: Windows
   extracts it to a temporary folder and the application does not start.
2. Open the extracted folder and double-click qicom.exe

In both cases:

- On first launch the blue "Windows protected your PC" screen
  (SmartScreen) may appear. Press "More info" and then "Run anyway" only
  if the checksum matches and your organisation's policy explicitly allows
  the test.

  The SmartScreen "unrecognized app" warning is also due to the lack of a
  publicly trusted signature. It is not, however, the same thing as a
  malware detection. If Defender or an EDR shows a threat name or
  quarantines the file, do not disable it and do not create exclusions:
  send IT the product, the full detection name, the SHA-256 hash and the
  time of the event.
- On Windows 11 with Smart App Control turned on, Windows can block the
  installer, the application or the uninstaller because they are not
  digitally signed, and it does not offer "Run anyway". Report it to the
  test lead instead of turning the protection off.

The first launch is slower than the others (Windows scans the files the
first time). A splash screen with the logo appears, then the mode
selection window.


Linux (x86-64)
--------------
The verified local reference is Ubuntu 24.04 with glibc 2.39. The bundle
is built on the ubuntu-latest runner: check the actual version stated for
the build. An archive built on a recent distribution is not guaranteed to
work on an older one; the system glibc is not included. Linux ARM and
32-bit bundles are not supported.

On Debian and Ubuntu use the .deb package:

    sudo apt install ./QICOM-linux-x64.deb

apt also installs the system libraries that Qt needs. QICOM appears in the
applications menu and can also be launched from a terminal with: qicom
The files are in /opt/qicom; the user's data stays in their home folder.
To verify the installed files: dpkg --verify qicom
To uninstall: sudo apt remove qicom
If apt refuses the package because of the libc6 version, the system is
older than the one the build was made on: use a more recent system, do not
force the installation.

On other distributions unpack the .tar.gz archive preserving permissions
and launch qicom from its folder.
If Qt libraries are missing or the graphics driver is not compatible,
write down the error and the distribution version for the test lead.


Updates
-------
On first launch a copy downloaded from qicom.ch asks whether it may check
for a newer version every time it starts. The check reads a small file from
github.com, where qicom.ch publishes its downloads, and sends nothing about
you or your data. You can change the answer at any time with Help > Check
for Updates at Startup, and check on demand with Help > Check for
Updates...

Nothing is downloaded or installed without asking you. If you accept an
update, QICOM downloads it, verifies its size and SHA-256, asks you to save
any unsaved changes, closes and installs it:

  Windows (installed with QICOM-Setup.exe): the new setup runs silently in
      the same folder, for the same users, and QICOM starts again. Windows
      may ask for permission to make changes.
  Linux (.deb): the new package is installed after you enter the
      administrator password, then QICOM starts again.
  Linux (.tar.gz): the folder is replaced with the new version and QICOM
      starts again.
  macOS and the portable Windows folder: QICOM opens the download page
      instead.

The update is unsigned like the first download: on Windows 11 with Smart
App Control turned on, it is blocked just as the installer is.


If something does not work
--------------------------
When reporting a problem, attach the log file. It is here:

  macOS:    ~/Library/Logs/qicom/qicom.log
  Windows:  %LOCALAPPDATA%\qicom\Logs\qicom.log
            (paste it into the File Explorer address bar)
  Linux:    ~/.local/state/qicom/log/qicom.log

Help > Report a Bug... saves the selected errors, the build data and the
end of the log into a text file to attach. QICOM never sends it by
itself; read it before sending it, because it can contain file names.

Session data (projects, ROIs, results) is here:

  macOS:    ~/Library/Application Support/qicom
  Windows:  %LOCALAPPDATA%\qicom
  Linux:    ~/.local/share/qicom (preferences in ~/.config/qicom)

To uninstall: on Windows, if you used the installer, with "Uninstall
QICOM" in the installation folder or from Settings > Apps; on Debian and
Ubuntu with sudo apt remove qicom; otherwise delete the application
folder. To clean up everything, also delete the data folders above (on
Windows the log is already inside %LOCALAPPDATA%\qicom).


Metrics shown as not available
------------------------------
Some metrics can be listed as NOT available. This is not a defect.

The downloads on qicom.ch do not include the learned-metric libraries
(torch, piq, lpips), which would make them about ten times larger. In those
builds MS-SSIM, FSIM, GMSD, VIF, HaarPSI, LPIPS, DISTS and canonical BRISQUE
are omitted, with the missing library stated as the reason. Every other
metric works.

Some metrics also need model files that are not included in any bundle:
canonical NIQE (about 8 KB, from LIVE) and, in builds with the learned
metrics, LPIPS and DISTS (about 760 MB together - more than the rest of the
application) and canonical BRISQUE. QICOM never downloads them on its own,
and in particular never during an analysis: if they are missing, the metric
is simply omitted with the reason stated, without any network access.

Enabling them takes an explicit step that you decide on: when a selected
metric needs a missing model, the list of metrics (Analyze step, or
Settings > Default metrics) shows a "Download missing models" button,
which first states how much will be downloaded. Every file is verified
against a known size and SHA-256: if it does not match, it is refused.


Network connections
-------------------
QICOM opens a network connection only for the model download above, for
the official IBSI resources of the IBSI verification (after you agree), and
for the update check, if you allowed it or ask for it (see Updates). No
analysis ever opens one. Everything else - images, ROIs, results, reports -
stays on your machine.
